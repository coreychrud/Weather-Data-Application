# Weather Data Application

A small FastAPI service that validates forecast requests and retrieves live data
from the [Open-Meteo Forecast API](https://open-meteo.com/en/docs).

## Features

- Current, hourly, and daily forecast weather
- Single-day forecast and historical weather endpoints
- Metric and imperial units
- Coordinate and forecast-range validation
- Async upstream requests with a shared, configurable HTTP client
- Explicit gateway timeout/error responses
- OpenAPI documentation generated by FastAPI
- Automated API tests and a production-ready Docker image

## Run locally

Python 3.11 or newer is required.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
uvicorn app.main:app --reload
```

Open the interactive API docs at <http://127.0.0.1:8000/docs>.

## Frontend

The project also includes a responsive React/D3 frontend in the `frontend`
directory. Select a location on the US map to explore current conditions, a
seven-day forecast with hourly detail, or hourly observations for a historical
date. Selecting a state zooms the map for more precise location selection, and
the interface supports metric and imperial units.
Run it separately from the backend:

```powershell
cd frontend
npm install
npm run dev
```

Open the frontend at <http://localhost:5173>.

## Request a forecast

```bash
curl --get 'http://127.0.0.1:8000/api/v1/forecast' \
  --data-urlencode 'latitude=41.8781' \
  --data-urlencode 'longitude=-87.6298' \
  --data-urlencode 'forecast_days=3' \
  --data-urlencode 'timezone=auto' \
  --data-urlencode 'units=metric'
```

Request a forecast for one specific day:

```bash
curl --get 'http://127.0.0.1:8000/api/v1/weather/forecast/2026-10-27' \
  --data-urlencode 'latitude=41.8781' \
  --data-urlencode 'longitude=-87.6298' \
  --data-urlencode 'timezone=auto' \
  --data-urlencode 'units=metric'
```

Request historical weather for one specific day:

```bash
curl --get 'http://127.0.0.1:8000/api/v1/weather/historical/2020-01-15' \
  --data-urlencode 'latitude=41.8781' \
  --data-urlencode 'longitude=-87.6298' \
  --data-urlencode 'timezone=auto' \
  --data-urlencode 'units=metric'
```

Dates use ISO 8601 `YYYY-MM-DD` format. The forecast route is limited by the
upstream forecast horizon. The historical route uses Open-Meteo's Archive API,
whose reanalysis data is available from 1940, with dataset-specific delays and
coverage. Invalid or unavailable dates return `422`.

Query parameters:

| Name | Required | Default | Valid values |
| --- | --- | --- | --- |
| `latitude` | yes | — | `-90` to `90` |
| `longitude` | yes | — | `-180` to `180` |
| `forecast_days` | no | `7` | `1` to `16` |
| `timezone` | no | `auto` | IANA time zone or `auto` |
| `units` | no | `metric` | `metric` or `imperial` |

## Configuration

| Environment variable | Default | Purpose |
| --- | --- | --- |
| `OPEN_METEO_BASE_URL` | `https://api.open-meteo.com/v1` | Open-Meteo API base URL |
| `OPEN_METEO_ARCHIVE_BASE_URL` | `https://archive-api.open-meteo.com/v1` | Open-Meteo Archive API base URL |
| `HTTP_TIMEOUT_SECONDS` | `10` | Upstream request timeout |

## API behavior

- `GET /health` checks that this process is running. It deliberately does not
  call Open-Meteo, so orchestration health checks do not consume upstream quota.
- `GET /api/v1/forecast` returns `422` for invalid inputs, `504` when Open-Meteo
  times out, and `502` when the upstream service returns an invalid response.
- `GET /api/v1/weather/forecast/{weather_date}` retrieves forecast data for one
  date.
- `GET /api/v1/weather/historical/{weather_date}` retrieves reanalysis-based
  historical weather for one date.

The service is intentionally stateless. Before adding a database, define whether
the product needs historical snapshots, analytics, or only fresh forecasts. For
high-traffic use, add a short-TTL cache keyed by coordinates and request options.
